# Multi-Provider Consultation Log — Strategy — 2026-06-12

## Вопрос
Как правильно организовать диалог агента VeAI с бесплатными веб-чатами для максимально эффективного решения задач?

## GLM (чат 86515cb8, Deep Think, 11382+ симв)
- Уверенность: код-ревью 90%, PDF 60%, логи 85%, blob 70%, параллельные 95%
- Ключевой принцип: сжимать вход + декомпозировать задачи (8-32K лимит)
- Паттерн «Ревью с фокусом»: сначала сигнатуры + проблемный метод → потом контекст по запросу
- Промпт-шаблон: [КОНТЕКСТ] → [СИГНАТУРЫ] → [МЕТОД ДЛЯ РЕВЬЮ]
- Архитектура: VeAI ←→ Playwright MCP ←→ Браузер ←→ Чаты

## DeepSeek (чат 735ff162, 9985 симв)
- Уверенность: 90%
- 5 ограничений бесплатных чатов: короткий контекст, rate limits, нет tool calling, медленная генерация, риск потери контекста
- Паттерн «Chunk + Summarize» для документов (по 4000 токенов)
- Паттерн маркеров: [THINK] для рассуждений, [RESPONSE] для результата
- Round-robin + fallback для rate limits
- Контекстный checkpointing

## Qwen (чат a2cac957, 1619+ симв)
- Уверенность: 90%
- **Критическое:** Network Interception вместо DOM чтения — SSE/WebSocket перехват в 10-100 раз быстрее
- Пул браузерных контекстов — не открывать новую вкладку на каждый запрос
- Blob-download через page.on('download') — без записи на диск

## Консенсус
- ✅ Все 3: сжимать контекст + декомпозировать задачи
- ✅ Все 3: мультитурн вместо мегапромптов
- ✅ GLM+DeepSeek: чанкинг по 4K токенов для документов
- ⚠️ Разногласие: Qwen → Network Interception, GLM → DOM чтение + маркеры
- 🏆 Qwen предложение самое радикальное — SSE перехват вместо DOM

## Решение VeAI (оркестратор)
Принят гибридный подход:
1. **DOM-чтение** — основной метод (простой, работает для всех провайдеров)
2. **SSE-перехват** — резервный (быстрее, но сложнее, теряется при beforeunload)
3. **Контекстный checkpointing** — обязателен для длинных сессий
4. **5 паттернов промптов** — реализованы в SKILL.md v12.0
